# What is the smallest useful adoption step?

The smallest useful path is:

1. read [Introduction](/docs/intro)
2. read [Execution Modes](/docs/execution-modes)
3. read [Checkpoint Reporting](/docs/checkpoint-reporting)
4. run [Quick Start](/docs/quickstart) when you are ready to bootstrap the repo

That is enough to understand the basic contract before you ask an agent to change code under VibeGov.

If that feels heavier than the work deserves, keep the workflow lighter: write the issue clearly, name the expected proof, and record blockers instead of losing them in chat.
